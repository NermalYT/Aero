# Aero 1.1: open-source research and what was adopted

Two parts. **Part 1** is what Aero 1.1 actually took from other projects, tied to code and measurements in this
repository. **Part 2** is the evidence gathered on 2026-10-09 for every candidate (GitHub API numbers, licenses, file
paths, decisions), kept as recorded.

## Part 1: decisions as implemented in 1.1.0

No third-party source code was copied or vendored into Aero 1.1. Every new module is Aero's own code. Techniques
were adopted where a documented interface or a measured result supported them.

## Cross-cutting findings

1. **License traps found:**
   - crawl4ai has an attribution clause appended to Apache-2.0 and ships a vendored html2text (GPL-3.0 upstream).
   - OmniParser's repo LICENSE is CC-BY-4.0 while the README badge says MIT, and its `icon_detect` weights are AGPL.
   - RustDesk is AGPL-3.0.
   - The MCP repos are mid-relicense from MIT to Apache-2.0 (CC-BY-4.0 for docs), and GitHub reports NOASSERTION.
2. **Aero's existing dependencies already cover the key techniques:**
   - Python Playwright v1.63.0 has a public `Page.aria_snapshot(mode="ai")` that emits `[ref=eN]` refs, and `aria-ref=` is a built-in selector engine.
   - `uiautomation` 2.0.29 exposes `Invoke`/`SetValue`/`Toggle`/`Select`/`Expand` plus `PostMessage`/`SendMessage`.
3. **No examined Windows agent does true background control by default.** UFO and Windows-MCP both bring the target window to the foreground. Focus-free actions come from:
   - UIA patterns (`InvokePattern`, `ValuePattern`, ...);
   - Win32 `WM_*` messages, e.g. pywinauto's `HwndWrapper.click()` and `send_chars()`;
   - application COM APIs (UFO's WinCOM receivers).
4. **llama-server cannot change GPU layers live.** `POST /props` lists "Options: None yet". Router-mode load/unload restarts a child process. Plan for "reload with new args" instead.
5. **Remote-viewer detection is only documented for RDP**, via the WTS APIs. Third-party tools such as RustDesk expose no documented signal.
6. **Telemetry is on by default** in browser-use and Windows-MCP (both PostHog). browser-use's device id is a SHA-256 of MAC address + hostname.

## 1. microsoft/UFO

- **Inspected:** 2026-10-09. **Stars / forks / watchers:** 9,975 / 1,069 / 506. Open issues + PRs: 87.
- **Last push:** 2026-10-07T06:32:53Z. **Latest release:** v3.0.10, 2026-09-22 (previous: v3.0.9 2026-09-14, v3.0.8 2026-08-10)
- **License:** MIT (`LICENSE`: Copyright (c) Microsoft Corporation, MIT License)
- **CI evidence:** `.github/workflows/` contains only `document_deploy.yml`. No test or lint workflow was found.

### Background vs. foreground control (key question)

**`ufo/automator/ui_control/controller.py`: control path**

`ControlReceiver.__init__` calls `self.control.set_focus()`, or `self.application.set_focus()` when there is no control (lines 64–68). Every action executed through a receiver therefore foregrounds the target first.

**`ufo/automator/ui_control/controller.py`: clicking**

- `click_input()` reads the `CLICK_API` config value: `"click"` calls pywinauto `click`; anything else calls pywinauto `click_input`, which drives the real mouse. `config/ufo/system.yaml` sets the default `CLICK_API: "click_input"` (line 50).
- `click_on_coordinates()`, `drag_on_coordinates()` and `scroll()` call `self.application.set_focus()` and then pyautogui (`pyautogui.click`, `dragTo`, `vscroll`/`hscroll`). These are true SendInput-style actions that move the cursor. `pyautogui.FAILSAFE = False` is set at line 42.

**`ufo/automator/ui_control/controller.py`: text input**

- `set_edit_text()` reads `INPUT_TEXT_API` (default `"type_keys"`, `system.yaml` line 52). Fallback chain: pywinauto `set_edit_text` (UIA ValuePattern) when configured → `type_keys` (keyboard injection) → pyautogui `hotkey/press/write` as a last resort.
- `keyboard_input()` with `control_focus=True` calls `set_focus()` and then `type_keys`.

**Background-capable path.** The "API" half of the hybrid is COM automation: `ufo/automator/app_apis/basic.py` uses `win32com.client.Dispatch(self.clsid)`. App receivers exist for Word, Excel, PowerPoint, web and shell (`ufo/automator/app_apis/*`), exposed as local MCP servers (`ufo/client/mcp/local_servers/{excel,word,ppt}_wincom_mcp_server.py`). These operate on the document object model without UI focus.

**Picture-in-Picture (non-disruptive) desktop.** Promoted in `documents/docs/ufo2/overview.md`, but `documents/docs/faq.md` says PiP mode is planned for future releases, and code search found no implementation.

**Does UFO use pywinauto?** Yes, as the core dependency. `requirements.txt` pins `pywinauto==0.6.8` (the 2019 release, not 0.6.9), plus `uiautomation==2.0.18`, `pyautogui==0.9.54`, `comtypes==1.2.0` and `pywin32>=310`.

### UIA tree inspection: `ufo/automator/ui_control/inspector.py`

- `BackendFactory` offers `uia` or `win32` backends.
- `UIABackendStrategy` works as follows:
  - enumerates top-level windows with `Desktop(backend="win32").windows()`;
  - walks descendants through raw comtypes `IUIAutomation` with a cached `CreateCacheRequest()` covering ControlType, Name and BoundingRectangle (`_get_cache_request`, approx. lines 325–331), filtered by a control-type condition. This batches cross-process COM calls and is directly applicable to Aero's `uiautomation` tree walk.
- `uiautomation` is used only for `get_check_state`.

### Runtime and weight

- The README badge says Python 3.10 | 3.11.
- Dependencies are heavy: `langchain`, `sentence-transformers==2.6.0` (torch), `faiss-cpu`, `openai`, `anthropic`, `azure-identity*`, `gradio_client`, `flask` + `fastapi`, `pandas==1.4.3`, `matplotlib`.

### Local-first, security and decision

- **Local-first/offline:** Not by default. It is built around hosted LLM APIs (OpenAI/Azure/Anthropic), and the README quick-start steps tell the user to add API keys to the config.
- **Security/privacy notes:** `pyautogui.FAILSAFE = False` disables the corner-abort safety. Focus stealing interferes with the user. The COM path runs with full user privileges.
- **Decision: architectural reference.**
  - UFO is not a background-control solution. It foregrounds the window, and its default click and type paths inject real input.
  - Reuse two ideas, without the code:
    1. A pattern-first action ladder: ValuePattern, then keyboard, then pointer.
    2. A COM-API lane for Office apps, plus UIA CacheRequest batching.

## 2. browser-use/browser-use

- **Inspected:** 2026-10-09. **Stars / forks / watchers:** 117,403 / 12,991 / 476. Open issues + PRs: 519.
- **Last push:** 2026-10-09T17:36:28Z. **Latest release:** 0.13.11, 2026-10-07 (0.13.10 and 0.13.9 both 2026-09-04)
- **License:** MIT (`LICENSE`: Copyright (c) 2024 Gregor Zunic). The Python library is MIT.
- **CI evidence:** `claude.yml`, `docker.yml`, `eval-on-pr.yml`, `install-script.yml`, `lint.yml`, `package.yaml`, `publish.yml`, `stale-bot.yml`, `test.yaml` (`build-base-image.yml.disabled` is disabled).

### DOM state serialization (element indexing)

**`browser_use/dom/service.py`: raw DOM capture over CDP directly (no Playwright)**

- Calls: `DOMSnapshot.captureSnapshot` (~l.571), `DOM.getDocument` (~l.583), `Accessibility.getFullAXTree` (~l.379), `Page.getLayoutMetrics` (~l.228) and `Runtime.evaluate` (JS event-listener detection, ~l.465).
- Transport is the `cdp-use==1.4.5` dependency.

**`browser_use/dom/serializer/serializer.py`: `DOMTreeSerializer.serialize_accessible_elements()` pipeline**

1. Build a simplified tree that includes open and closed shadow roots and iframes.
2. Run `PaintOrderRemover` (`serializer/paint_order.py`) to drop elements occluded by later-painted elements.
3. Optimize the tree.
4. Filter bounding boxes: children contained in a "propagating" clickable parent (e.g. a button wrapping a span) are excluded.
5. Assign interactive indices.

**Index allocation (`_allocate_selector_index`, ~l.649)**

- The model-visible index is the CDP `backend_node_id` itself when unique, so it stays stable across steps.
- On collision a synthetic index above all reserved ids is used.
- `selector_map[index] -> EnhancedDOMTreeNode`.

**Text format (`serialize_tree`, ~l.989)**

Tab-indented lines `[index]<tag attrs>`. A `*` prefix marks elements new since the previous step. Shadow hosts are tagged `|SHADOW(open)|` / `|SHADOW(closed)|`, SVG children are collapsed, scrollable containers and iframes are shown, and `<select>` options and ARIA min/max/now are folded in as "compound components".

**Attribute whitelist and interactivity**

- `browser_use/dom/views.py` `DEFAULT_INCLUDE_ATTRIBUTES` covers title, type, checked, id, name, role, value, placeholder, alt, aria-label/expanded/checked/value*, and validation attributes (pattern, min, max, minlength, maxlength, step, accept, multiple, inputmode, ...).
- `browser_use/dom/serializer/clickable_elements.py` holds the interactivity heuristics.

### Would the full agent loop duplicate Aero's?

Yes. `browser_use/agent/service.py` `class Agent` owns its own loop: `step()`, a `max_steps` budget with budget-warning messages injected into the prompt (~l.1548–1572), its own system prompts (`browser_use/agent/system_prompts/*.md`), its own LLM clients (openai, anthropic, google-genai, groq, ollama are all core dependencies) and its own tool registry. Embedding it would nest a second agent inside Aero's.

### Runtime and weight

- `pyproject.toml` requires Python `>=3.11,<4.0` and has **37 core dependencies** (36 exact `==` pins; `anthropic` is a range). Notable ones: `posthog`, `google-api-python-client`, `google-auth-oauthlib`, `mcp==2.1.1`, `reportlab`, `python-docx`, `pypdf`, `browser-use-sdk`, `browser-harness`.
- No torch.

### Local-first, security and decision

- **Local-first/offline:** The library runs locally with a local Chrome, and Ollama is supported.
- **Security/privacy notes:**
  - Telemetry is on by default: `browser_use/config.py` reads `ANONYMIZED_TELEMETRY` with default `'true'` (l.58–59).
  - It posts to PostHog EU (`browser_use/telemetry/service.py`, `POSTHOG_HOST = 'https://eu.i.posthog.com'`).
  - The device id is a SHA-256 hash of `uuid.getnode()` (the MAC address) plus the hostname (`_machine_fingerprint`, l.53–62).
  - `BROWSER_USE_CLOUD_SYNC` defaults to the telemetry value. `browser_use/sync/service.py` only sends events when the user is authenticated.
- **Decision: architectural reference.**
  - Adopt three serializer ideas in Aero's own Playwright DOM-ref module: (1) stable ids derived from backend node ids; (2) `*new` markers between steps; (3) paint-order and contained-child pruning, plus validation attributes.
  - Do not take the dependency. Its loop, LLM stack and default telemetry conflict with Aero.

### Where the code lives

`src/README.md` states that the source now lives in the Playwright monorepo at `packages/playwright-core/src/tools/mcp/`. That directory contains `browserFactory.ts`, `cdpRelay.ts`, `config.ts`, `program.ts`, `protocol.ts`, `watchdog.ts`, etc. This repo is a thin wrapper: `package.json` dependencies are `playwright` / `playwright-core` `1.64.0-alpha-…`, with `engines.node >=18`.

### Tool schemas (README, generated by `update-readme.js`)

- **`browser_snapshot`** (read-only): `target?` (snapshot a subtree), `filename?` (write to file instead of returning it), `depth?`, `boxes?` (appends `[box=x,y,width,height]` in viewport CSS pixels).
- **`browser_click`**: `element?` (a human-readable element description that the README says is used to obtain permission), `target` (required; an exact element ref from the snapshot, or a unique selector), `doubleClick?`, `button?`, `modifiers?`.

Note that the parameter is now **`target`**, not the older `ref`. The same `target` + `element` pair appears on hover, type, drag, select, verify, etc.

**`browser_find`** searches the snapshot by `text` or `regex` and returns matching nodes with their path and refs. The README describes it as cheaper than a full snapshot.

**Other tools.** 72 tools listed in the README, including `browser_run_code_unsafe` (arbitrary code), cookie and localStorage CRUD, route mocking, tracing and video.

  - whether the CM process exits after the last viewer disconnects, or stays resident;
  - whether the Flutter build always uses the same flag.
- **Impersonation is a bad idea:** acting as the `_cm` IPC listener would intercept RustDesk's connection-manager traffic. It is fragile, security-sensitive and an AGPL protocol surface.
- **Inference (not tested):** RustDesk mirrors the existing console session, so the WTS APIs in section 12 will report a console session (protocol type 0), not RDP, during a RustDesk session.

### Decision

**Decision: rejected** (as code and as an integration contract).

- If Aero wants a "remote viewer present" safety signal, implement RDP via the documented WTS APIs.
- Optionally add an **opt-in, clearly labelled heuristic** for known remote-control processes (RustDesk `--cm`), shown to the user as "best-effort".

## 12. Windows RDP detection (Microsoft Learn)

- **Inspected:** 2026-10-09 via WebFetch.
- **Page update dates:** WTS_INFO_CLASS 2025-11-21; WTSQuerySessionInformationW, WTSEnumerateSessionsW, GetSystemMetrics and WTSRegisterSessionNotification 2025-07-01; WM_WTSSESSION_CHANGE 2025-10-22; "Detecting the RDS environment" 2025-03-13.

### APIs

All are in `Wtsapi32.dll` (header `wtsapi32.h`, minimum Windows Vista / Server 2008) unless noted.

**`WTSQuerySessionInformationW(hServer, SessionId, WTSInfoClass, LPWSTR *ppBuffer, DWORD *pBytesReturned)`**

- Pass `WTS_CURRENT_SERVER_HANDLE` and `WTS_CURRENT_SESSION` for the caller's session. Use `WTS_CURRENT_SESSION` only on the local server.
- Free the buffer with `WTSFreeMemory`.
- Returns nonzero on success. On failure call `GetLastError`.
- If Remote Desktop Services isn't running, the call fails; use `ProcessIdToSessionId` instead.
- Querying another user's session requires Query Information permission.
- The documented physical-console check is: query `WTSClientProtocolType` for `WTS_CURRENT_SESSION`; a result of 0 means attached to the physical console.

**`WTSClientProtocolType`** (USHORT, from the WTS_INFO_CLASS page):

| Value | Meaning |
|---|---|
| 0 | console session |
| 1 | the page now says only that the value is retained for legacy purposes (historically ICA) |
| 2 | RDP protocol |

**`WTSConnectState`** returns a `WTS_CONNECTSTATE_CLASS`. Values are implicit enum order from 0:

| Value | Name | Meaning |
|---|---|---|
| 0 | `WTSActive` | user logged on and connected |
| 1 | `WTSConnected` | connected to client |
| 2 | `WTSConnectQuery` | connecting |
| 3 | `WTSShadow` | shadowing another session |
| 4 | `WTSDisconnected` | signed in, client disconnected (e.g. exited to lock screen) |
| 5 | `WTSIdle` | waiting for a client |
| 6 | `WTSListen` | listener, no user |
| 7 | `WTSReset` | being reset |
| 8 | `WTSDown` | down due to error |
| 9 | `WTSInit` | initializing |

**`WTSIsRemoteSession`** (info class) returns TRUE for a remote session. It is local-machine only (`WTS_CURRENT_SERVER_HANDLE`) and unsupported on Vista and Server 2008.

**`WTSEnumerateSessionsW(hServer, Reserved=0, Version=1, PWTS_SESSION_INFOW *ppSessionInfo, DWORD *pCount)`**

- Returns an array of `WTS_SESSION_INFOW` (session id, WinStation name, state). Free it with `WTSFreeMemory`.
- Enumerating a session requires the Query Information permission. RD Virtualization Host VMs require Administrators.

**`GetSystemMetrics(SM_REMOTESESSION = 0x1000)`** (User32)

- Nonzero when the process is associated with a Terminal Services client session; 0 for the console session.

**`GetSystemMetrics(SM_REMOTECONTROL = 0x2001)`**

- Nonzero when the current session is being remotely controlled (shadowed), e.g. via tsadmin or shadow.exe.

**RemoteFX vGPU caveat** (from "Detecting the Remote Desktop Services environment"):

- On Windows 8 / Server 2012 and later, `SM_REMOTESESSION` can report a RemoteFX vGPU remote session as local.
- The documented fallback compares the current session id from `ProcessIdToSessionId` with `HKLM\System\CurrentControlSet\Control\Terminal Server\GlassSessionId`. If they differ, the session is remote.

**`WTSRegisterSessionNotification(HWND hWnd, DWORD dwFlags)`** with `NOTIFY_FOR_THIS_SESSION` or `NOTIFY_FOR_ALL_SESSIONS`

- Delivers `WM_WTSSESSION_CHANGE`.
- Every successful call must be paired with `WTSUnRegisterSessionNotification` before the window is destroyed.
- Before RDS dependencies start, the call may fail with `RPC_S_INVALID_BINDING`; wait for the `Global\TermSrvReadyEvent` event.
- Services should use `HandlerEx` instead.
- The numeric flag values (0/1) and the `WM_WTSSESSION_CHANGE` message number (0x02B1) were **not shown on the fetched pages**. Take them from the SDK headers.

**`WM_WTSSESSION_CHANGE`**: `lParam` is the session id. `wParam` values:

| Value | Code |
|---|---|
| 0x1 | `WTS_CONSOLE_CONNECT` |
| 0x2 | `WTS_CONSOLE_DISCONNECT` |
| 0x3 | `WTS_REMOTE_CONNECT` |
| 0x4 | `WTS_REMOTE_DISCONNECT` |
| 0x5 | `WTS_SESSION_LOGON` |
| 0x6 | `WTS_SESSION_LOGOFF` |
| 0x7 | `WTS_SESSION_LOCK` |
| 0x8 | `WTS_SESSION_UNLOCK` |
| 0x9 | `WTS_SESSION_REMOTE_CONTROL` (re-check `SM_REMOTECONTROL`) |
| 0xA | `WTS_SESSION_CREATE` (reserved) |
| 0xB | `WTS_SESSION_TERMINATE` (reserved) |
| 0xF | `WTS_SESSION_DESKTOP_READY` |

### Suggested Aero use

Implement with `ctypes`; no new dependency.

**At startup and on demand, compute `remote = True` when any of these holds:**

- `GetSystemMetrics(SM_REMOTESESSION) != 0`;
- `WTSClientProtocolType == 2`;
- the GlassSessionId check says the session is remote.

**Also record:**

- `controlled = GetSystemMetrics(SM_REMOTECONTROL) != 0`;
- `state = WTSConnectState`.

**Live updates:** a hidden message-only window registered with `NOTIFY_FOR_THIS_SESSION` re-evaluates the state on `WTS_REMOTE_*`, `WTS_SESSION_LOCK/UNLOCK` and `WTS_SESSION_REMOTE_CONTROL`.

**Limitation:** none of these APIs detect third-party screen-sharing tools (RustDesk, VNC, etc.) that capture the console session. See section 11.

### Decision

**Decision: direct dependency** (OS API).

- These are documented, stable Win32 APIs available on every supported Windows version.
- Linux and macOS need separate mechanisms, which were out of scope here.
