# Aero 1.2: performance

Measured 2026-10-11 on the test PC: Windows 11 Pro 26200, AMD Ryzen 9 9950X3D2, 62 GB DDR5, NVIDIA RTX 5080 16 GB
(driver 616.92), llama.cpp b11501 (CUDA 13.4). Raw results: `docs/evidence/`.

## 1. Router decisions

`validation/bench_router_intents.py`, router model MiniCPM5-2B Q4_K_M, 10 threads, the 50-request set and the 25
held-out requests (written in 1.1 before any tuning, never tuned on). Same session for both versions.

| | 1.1 (CPU) | 1.2 (CPU) | 1.2 (GPU) |
|---|---|---|---|
| Routed well, 50 requests | 50 / 50 | 50 / 50 | GPU_50_OK |
| Routed well, 25 held-out | 22 / 25 | **23 / 25** | GPU_HO_OK |
| Decision p50 / p95, 50 requests | 2,803 / 3,861 ms | **1,639 / 2,153 ms** | GPU_50_MS |
| Decision p50, held-out | 2,369 ms | **1,808 ms** | GPU_HO_MS |
| Tokens written per decision (median) | 76 | 44 | 44 |

Where the time went: the prompt (rules + catalog) was already cached, so a decision's cost is the JSON it writes, at
about 40 tokens/s on this CPU. 1.2 asks only for what Aero uses. One finding shaped the form: without the short
`intent` field written first, the 2B model labelled five real requests "trivial" and picked no tools (45/50); with
it, accuracy came back to 50/50 at 44 tokens. Greetings and thanks skip the router entirely (0 ms).
Held-out misses left: "Turn the volume down" (no volume tool exists) and "Fill out the contact form on example.org
with my name" (asks for the user's name).

## 2. Authority model (full auto)

`validation/bench_authority.py`, 32 decisions, two runs each, CPU, 10 threads; details in `V1.2_AUTONOMY.md`.
Qwen3-4B-Instruct-2507 Q4_K_M: 32/32, no trap allowed, 2.9 s median per decision. A live decision including starting
its server took 5.6 s.

## 3. Models bigger than the GPU

`validation/bench_bigmodel.py`, context 8,192, q8_0 KV, 2,200-token prompt, 128 tokens, second run; details in
`V1.2_BIG_MODELS.md`.

| Model | VRAM used | Plan | Generation |
|---|---|---|---|
| Llama-3.3-70B Q6_K (53.9 GB) | 12.4 GB | whole layers | 1.01 tok/s |
| | 12.3 GB | attention on GPU, feed-forward in RAM | 1.06 tok/s |
| | 12.5 GB | layers + n-gram speculation | 1.15 tok/s |
| | 12.7 GB | **layers + Llama-3.2-1B draft** | **4.85 tok/s** |
| Gemma-3-27B Q8_0 (26.7 GB) | 2.8 GB | whole layers (fits a 4 GB card) | 1.93 tok/s |
| | 3.1 GB | **layers + Gemma-3-1B draft** | **2.59 tok/s** |

The RAM part of the model is read once per token from DDR5 (about 44 GB for the 70B), which bounds generation near
1 token/s whatever the placement. A draft model of the same family lets the big model check up to eight tokens per
pass over its weights.
