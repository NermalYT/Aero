What 1.0 already had, and 1.1 extends rather than replaces:

| Area | 1.0 | 1.1 builds on it in |
|---|---|---|
| CPU router | JSON-schema decision (tools, think, plan, review), fixed prompt for caching | `capabilities.hint_tools`, `pipeline.app_context` |
| Tool registry | name, schema, permission category, `available()` | `capabilities.py` (typed metadata per tool) |
| Agent loop | approvals per category, subagents one level deep, Stop per chat | `agent.exec_tool` gates, task graph, questions, locks |
| Windows app control | UIA tree + PrintWindow; Invoke/Toggle/Select/SetValue; PostMessage clicks and WM_CHAR; `input="real"` borrowed the real mouse/keyboard automatically when suggested; chords always used the real keyboard | `tools/apps.py` rewritten around honest control modes |
| Desktop control | pyautogui, full screen | consent + idle wait + exclusive lock (`input_guard.py`) |
| Browser | Playwright, one visible persistent context, numbered refs, `browser_read` capped at 40,000 chars | background mode, per-agent tabs, whole-page sections (`extraction.py`) |
| Local Only / strict offline | network tool categories hidden; httpx transport check; audit log | same, plus request blocking inside the browser |
| Tuning | tuner + HAPO profiles; `-ngl`, `--n-cpu-moe`; VRAM from nvidia-smi or llama.cpp's buffer report | `vram_policy.py` (Remote Mode) |
| Skills | SKILL.md from data/skills and Claude/Codex folders | built-in skills folder |

## What could not be measured here

- A real inbound Remote Desktop or RustDesk session (nobody connected from another machine during this work).
- macOS and Linux desktops (CI runs the unit tests there; nothing interactive).
- AMD and Intel GPUs.
- A Gmail account through an MCP server or a signed-in browser (no account was used).
- Main-model tokens per second while background jobs run (the Qwen model was only loaded for the Remote Mode
  measurement, not for an agent session).
