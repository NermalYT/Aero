# Aero 1.1 architecture

1.1 adds one coordinated execution layer to 1.0's router and agent loop. It does not add a second agent framework:
every model (the local model, Claude and ChatGPT through their passes) still runs tools through
`agent.exec_tool`, and that is where the new rules apply.

## A request, end to end

```
user message
  │
  ├─ router (CPU model, unchanged JSON grammar)            pipeline.route
  │     + capability hints (regex, no model call)          capabilities.hint_tools
  │     + app mentions (installed-app registry)            pipeline.app_context → app_registry.mentions
  │     = the tools the main model sees; "Apps: …" line in <turn_context>
  │
  ├─ local model loop                                       agent.run_local
  │     read-only calls from one step run side by side      agent._run_parallel (max 4)
  │     ask_user / get_answer                               agent.ask_user / agent.get_answer → clarifications.py
  │     every other call                                    agent.exec_tool:
  │         1. permission policy (ask / auto / off), Local Only, blocked tools, Mod sandbox   (as in 1.0)
  │         2. Strict Background Only refuses real-input calls                               input_guard.strict
  │         3. real input needs a grant ("Foreground control required" card), an idle user  input_guard
  │            and the exclusive input lock                                                  resources
  │         4. app actions own their window for the turn (one agent per window)              resources "window:<hwnd>"
  │         5. verify-before-repeat for consequential calls after a timeout                  task_graph ledger
  │         6. a task-graph node per call, "task" events for the UI                          task_graph.TaskGraph
  │         7. tools.run → result with an envelope; evidence note appended for the model     action_results
  │
  ├─ reviews, lessons, journal, shared learning                                          (as in 1.0)
  └─ end of turn: locks and grants released; on Stop the agent's browser tab is closed and a
     "finished / not finished" summary is shown                                              pipeline.run_turn
```

## New modules

| Module | Responsibility |
|---|---|
| `capabilities.py` | Typed metadata for every tool: capabilities (`app.launch`, `browser.read`, …), side effect, network, background or physical, resource locks, verification. `is_physical`, `read_only`, `tools_for`, and the router's capability hints. |
| `app_catalog.py` | Inspectable knowledge of ~45 well-known apps and services: names, program and process names, link schemes, best backends, notes. No paths, accounts or private endpoints. |
| `app_registry.py` | Installed and running apps. Windows: Start-menu `.lnk` (parsed in pure Python), Uninstall keys, App Paths, link-scheme handlers, `Get-StartApps` (AUMIDs), processes. Linux: `.desktop`. macOS: `.app` bundles. `resolve()` with confidence, reason and ambiguity; `mentions()`; `launch()` with verification and learned launch methods; trust of program folders. Cached in `data/apps.json`, re-scanned when the Uninstall keys or Start menu change. |
| `input_guard.py` | The real mouse and keyboard: Strict Background Only, grants (once / this task), user idle time (`GetLastInputInfo`), restoring the window that was in front. Only timing is read, never keys. |
| `resources.py` | Named locks shared by all agents (`window:<hwnd>`, `input:physical`, …): all-or-nothing acquisition, re-entrant per owner, bounded waits, `release_owner` on Stop and at the end of every turn. |
| `action_results.py` | The result envelope (`backend`, `attempted`, `success`, `verified`, `verification_method`, `side_effect`, `duration_ms`, `control_mode`, `focus`) and the one-line evidence note. |
| `task_graph.py` | Typed task nodes with the 12 states, a dependency scheduler with bounded concurrency that keeps going while one node waits for the user, saved graphs (`data/tasks/<id>.json`), and the operation ledger (`data/tasks/ops.json`) for unknown outcomes. |
| `clarifications.py` | Questions to the user: ask (deduplicated), validate answers (choices, yes/no, numbers), wait with Stop, expiry, kept in `data/tasks/questions.json` so an answer after the turn still reaches the chat. |
| `extraction.py` | Whole-page reading: metadata, blocks (in-page `BLOCKS_JS` or Python's `html.parser`), boilerplate and duplicate removal, sections under heading paths with ids, BM25 selection within a character budget, provenance and explicit flags for anything cut or unreadable. |
| `meetings.py` | Meeting records from emails: week ranges in the user's zone, iCalendar parsing (TZID, UTC, Outlook zone names), SEQUENCE updates, cancellations, conflicts, mentions without invitations, a `.docx` that is reopened and counted, never overwriting. |
| `remote_sessions.py` | Remote viewers: Windows RDP through the WTS API (verified), Linux logind/xrdp (verified), RustDesk (installed / running / probable `--cm` window / verified events pushed by an integration), other remote tools (running only, viewer unknown). States: local, remote_connecting, remote_active, remote_reconnecting, remote_disconnected, unknown. |
| `vram_policy.py` | Remote Mode: plans the GPU/CPU split from GGUF tensor sizes and llama.cpp's offload order, measures it from llama.cpp's buffer report after the reload, runs the state machine (NORMAL, SWITCHING, REMOTE, RESTORE_PENDING, RECOVERING, FAILED_SAFE) with debounce, cooldown, rollback, minimum free VRAM, and holds new chats during a reload. |
| `tools/app_tools.py` | `app_find`, `app_launch` |
| `tools/ask_tools.py` | `ask_user`, `get_answer` (run by the agent loop) |
| `tools/doc_tools.py` | `meeting_doc` |
| `skills_builtin/` | `meetings-from-email`, `roblox-launch`, `code-project-tests` |

## Changed modules

| Module | Change |
|---|---|
| `tools/apps.py` | Per-agent window sessions. Control mode per window (`probe`): ACCESSIBILITY_BACKGROUND, WINDOW_MESSAGE_BACKGROUND, FOREGROUND_CONSENT_REQUIRED, OBSERVE_ONLY (higher integrity level). Element ids checked against the window, process and latest view. Classic edits get `WM_SETTEXT` (read back with `WM_GETTEXT`), other fields ValuePattern (read back), push buttons `BN_CLICKED`, posted clicks and keys are checked by comparing the window's controls and picture. `FocusGuard` restores the window in front with `SetForegroundWindow` only and remembers combinations that steal focus. No picture of minimized or covered GPU windows instead of a screen grab of whatever covers them. `input="real"` and chords only with a grant. |
| `tools/browser.py` | Background (headless) mode by default, visible on request; one tab per agent; snapshot generations reject stale refs; `browser_read_sections`, `browser_extract`, `browser_tabs`, `browser_wait_for`; typed values read back; password fields refused; strict offline enforced by a route handler inside the browser. |
| `tools/web.py` | `fetch_url` returns sections with provenance and cached ids. |
| `tools/desktop.py` | Typing in chunks with Stop checks; Windows types through SendInput's Unicode mode (no clipboard); elsewhere the clipboard's previous text is restored. |
| `agent.py` | `exec_tool` gates, parallel read-only calls, questions, task graph, evidence notes, chat-scoped Stop. |
| `pipeline.py` | App context, capability hints, wait for a Remote Mode reload, lock release and the Stop summary. |
| `control.py` | Control mode and honest phrases ("… in the background", "… with your mouse and keyboard", "… is opening …"); no on-screen banner for background browsing. |
| `engine.py` | `-lv 4` where supported (newer llama.cpp logs buffer sizes only at trace level). |
| `gguf.py` | `read_tensors`, `layer_bytes` (MTP blocks counted as llama.cpp counts them). |
| `config.py` | Version 1.1.0, new settings, prompt changes, recognition of untouched 1.0 prompts on every OS. |
| `server.py` | `/api/questions`, `/api/answer`, `/api/tasks/{chat}`, `/api/apps*`, `/api/remote*`, `/api/resources`; Remote Mode reload hooks; `remote` in `/api/stats`. |
| `static/app.js`, `app.css` | Question cards, the foreground-control card, the live step list, verification badges, Settings → Apps, Remote Mode in Settings → Model & tuning and on the dashboard, Strict Background Only and browser mode in Settings → Tools. |

## Settings added (defaults)

`strict_background` false · `browser_mode` "background" · `app_scan_hours` 24 · `tool_policy.ask` "auto" ·
`remote_mode` "auto" · `remote_gpu_weight_fraction` 0.8 · `remote_min_free_vram_mb` 0 · `remote_debounce_s` 8 ·
`remote_restore_cooldown_s` 90 · `remote_providers` {rdp, rustdesk, logind: true} · `remote_allow_probable` false.

Older settings files load unchanged; missing keys take these defaults. Nothing rewrites tuning, HAPO, MCP or chat
files.

## Data written by 1.1

| File | Holds | Never holds |
|---|---|---|
| `data/apps.json` | app records, your aliases, disabled apps, launch methods that worked (method + target + counts) | anything an app showed |
| `data/tasks/<graph>.json` | intents, tool names, states, 200-character results | page text, email bodies, file contents |
| `data/tasks/questions.json` | questions and answers (kept a week after they close) | |
| `data/tasks/ops.json` | keys of consequential calls whose outcome is unknown (3 days) | their arguments |
| `data/remote_mode.json` | Remote Mode state, plan, measurements, history | |

## SSE events added

`question`, `waiting`, `foreground_request`, `task`, and `control` now carries `mode` and `text`. Tool results carry
`verified` and `mode` when the tool made a verification claim.
