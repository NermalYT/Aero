## UI (live, 2026-10-11 and 2026-10-12)

Real server, scripted model, browser pane at 1600×900: the ten workspaces listed, every panel renders without errors,
Library search (40 results for "irc server"), the dashboard steps aside while a workspace is open below 1,700 px,
Settings → Autonomy (modes, authority status, recent decisions), the queue card, authority badges. Fixes made from
this run: workspace list retries while the server starts, queued tool cards keep their state at the end of a turn,
the authority Install button only when none is installed, the xtool check no longer boots WSL.

Second run, on the real server with the integrations installed: the Flutter app running inside the Mobile workspace
and hot-reloaded from it; an image generated from the Create workspace; the Big models planner on the 70B (sizes of
split files summed, the draft model the user already has picked up); the 70B loaded and answering in the chat. Fixed
from this run: the image model listed as a chat model, superseded measurements shown in the Big models panel, rea's
MCP schemas breaking every request, and empty replies from a model that calls a tool it wasn't offered.

## NOT RUN

- **RAD Debugger debugging session over IPC** (launch, breakpoints, stepping, evaluate). The first time `raddbg.exe`
  listens, Windows Firewall asks the user; Aero does not answer security prompts or edit firewall rules. The gate and
  the session logic are covered by unit tests (`RadDebuggerExposure`).
- **`xlsx_recalc`**: LibreOffice is not installed on the test PC.
- **`xtool dev` build and install**: needs Xcode.xip and an Apple account, which are the user's own steps.
- **Flutter builds for Android, iOS and Windows desktop**: no Android SDK, Xcode or Visual Studio on the test PC.
  Web was built and run.
- **e2e on mobile apps**: not wired up in Aero (documented in the pack).
- **AirLLM with a 70B full-precision checkpoint**: a 140 GB download; 7B and 32B were measured.
- **Image generation on a physical 4 GB card**: emulated with `--max-vram` budgets on the 16 GB card (3.2 GB used at
  the 2 GiB floor).
- **Aero's own Node.js download**: the test PC already had Node.js, so Aero used it.
- **Integrations live on macOS and Linux**: only the unit tests run there, in CI.
- **AMD and Intel GPUs**: the planner, image generation (Vulkan) and AirLLM were measured on NVIDIA only.
